# ChitoProject

سامانهٔ دریافت و پیگیری پروژه با رابط‌های تلگرام و بله، پنل مدیریتی فارسی و آرشیو مشترک گفتگوها. پیام آغاز کوتاه است؛ ثبت پروژه فعلاً با انتخاب «کامپیوتر» شروع می‌شود.

## مسیر کار مشتری

کاربر از منوی خصوصی ثبت پروژه، پیگیری یا پشتیبانی را انتخاب می‌کند. فرم مرحله‌به‌مرحله در یک پیام کنترلی کوتاه پیش می‌رود. گفتگوی پشتیبانی از پایگاه‌داده بازیابی می‌شود و پیام‌های تازهٔ کاربر و تیم را در همان آرشیو نگه می‌دارد.

متن‌های مشتری دربارهٔ ثبت و پیگیری پروژه و بررسی تیم هستند و در رابط عمومی از واژهٔ «ربات» استفاده نمی‌کنند. منوی مشتری مسیر فعال‌سازی یا پنل همکاران را نشان نمی‌دهد.

## راه‌اندازی روی VPS

نصب تازه برای Ubuntu 24.04 و 26.04 آماده شده است. Python برنامه با uv و نسخهٔ 3.12.16 در `/opt/chitoproject-python` مدیریت می‌شود؛ Python سیستم نصب یا تغییر داده نمی‌شود. برای HTTPS مستقیم روی IP، Caddy باید گواهی کوتاه‌عمر IP را با پروفایل ACME `shortlived` بگیرد؛ تمدید خودکار باید فعال بماند. جزئیات و روند امن به‌روزرسانی در [راهنمای استقرار](docs/DEPLOYMENT_FA.md) آمده است.

```bash
git clone git@github.com:Alidl81/chitoproject.git /tmp/chitoproject-bootstrap
sudo bash /tmp/chitoproject-bootstrap/scripts/install-vps.sh git@github.com:Alidl81/chitoproject.git <domain-or-ip>
```

کد فعال‌سازی یک‌بارمصرف مالک اصلی در خروجی نصب چاپ می‌شود. آن را در `${PUBLIC_BASE_URL}/admin/activate` وارد کنید؛ کد ۲۴ ساعت اعتبار دارد و فقط یک بار پذیرفته می‌شود. اگر روی همین VPS پورت 443 برای سرویس دیگری رزرو باشد، نصب‌کننده از 9443 استفاده می‌کند و URL باید همان پورت را داشته باشد:

```text
https://<domain-or-ip>[:port]/admin/activate
```

توکن و نام کاربری ربات‌ها عمداً خالی می‌مانند. آن‌ها را در فایل خصوصی `/etc/chitoproject/chitoproject.env` بگذارید. نام کاربری‌ها را بدون `@` وارد کنید. سپس سرویس‌های مربوط را راه‌اندازی کنید:

```bash
sudo systemctl restart chitoproject-api chitoproject-worker chitoproject-telegram chitoproject-bale
cd /opt/chitoproject/app
sudo -u chitoproject /opt/chitoproject/venv/bin/python -m app.cli check-bots
```

برای این نصب، دستور به‌روزرسانی یک‌مرحله‌ای و توضیح رفتار Deploy در [راهنمای استقرار](docs/DEPLOYMENT_FA.md) است. اسکریپت checkout را بررسی می‌کند و فقط fast-forward انجام می‌دهد. فایل‌های برنامه را پس از تطبیق با نسخهٔ قبلی جایگزین می‌کند؛ از uv و همان محیط Python استفاده می‌کند، migration را اجرا می‌کند و سرویس‌های موجود را restart می‌کند. فایل `/etc/chitoproject/chitoproject.env`، دیتابیس و آپلودها را بازسازی یا جایگزین نمی‌کند. اگر فایل محلیِ ناشناخته‌ای پیدا کند، متوقف می‌شود.

اگر نصب را دستی انجام می‌دهید، نمونهٔ Caddy در `deploy/Caddyfile.example` و واحدهای systemd در `deploy/systemd/` هستند. راهنمای کامل در [راهنمای استقرار](docs/DEPLOYMENT_FA.md) آمده است.

## اجرای توسعه

از Python 3.12.16 استفاده کنید. نصب توسعه در ریشهٔ پروژه:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
cp .env.example .env
```

برای اجرای محلی، مقادیر `APP_ENV=development`، `DATABASE_URL=sqlite+aiosqlite:///./chitoproject-dev.db`، `SECRET_KEY` تصادفی و `UPLOADS_DIR=./data/uploads` را در `.env` بگذارید. برای Postgres، نشانی را به `postgresql+asyncpg://...` تغییر دهید. سپس:

```bash
python -m app.cli migrate
python -m app.cli issue-owner-code
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

در ترمینال‌های جداگانه اجرا کنید:

```bash
python -m app.bot_entry telegram
python -m app.bot_entry bale
python -m app.worker_entry
```

هر پیام‌رسانی که توکن ندارد غیرفعال می‌ماند. هیچ جدول در شروع وب‌سرور خودکار ساخته نمی‌شود؛ طرح پایگاه‌داده با Alembic مدیریت می‌شود.

## فعال‌سازی و تیم

- دستور `python -m app.cli issue-owner-code` یک کد محرمانهٔ یک‌بارمصرف صادر می‌کند. در ربات مشتری هیچ فرمان یا ورودی کدی نمایش داده نمی‌شود.
- مالک از پنل برای هر نقش یک لینک دعوت می‌سازد. همکار با همان لینک نام کاربری و رمز خود را می‌سازد؛ گرفتن شناسهٔ تلگرام یا بله لازم نیست.
- پس از عضویت، مالک می‌تواند از صفحهٔ تیم لینک اتصال یک‌بارمصرف تلگرام یا بله را برای حساب آن عضو بسازد. اتصال پیام‌رسان برای استفاده از منوی همکاران لازم است.
- نقش‌های مالک، مدیر پروژه، بازبین، همکار اجرایی و پشتیبانی مجوزهای متفاوت دارند. پنهان بودن یک دکمه جای کنترل دسترسی سمت‌سرور را نمی‌گیرد؛ هر مسیر مدیریتی مجوز خود را دوباره بررسی می‌کند.

شرح مجوزها و راهنمای پنل در [راهنمای مدیریت](docs/ADMIN_GUIDE_FA.md) است.

## آرشیو گفتگو و پاک‌سازی صفحه

هر پیام ورودی، پاسخ تیم، نسخهٔ ویرایش‌شدهٔ پیام کنترلی و اقدام Inline در آرشیو ذخیره می‌شود. پاک‌سازی از بخش پشتیبانی فقط پیام‌های همان نشست را برای حذف از صفحهٔ پیام‌رسان صف می‌کند و آرشیو سرور را دست‌نخورده می‌گذارد. تلگرام حذف پیام را پس از ۴۸ ساعت نمی‌پذیرد؛ نتیجهٔ حذف هر پیام به API همان پیام‌رسان وابسته است.

مالک اصلی می‌تواند از صفحهٔ گفتگو آرشیو را حذف کند. حذف آرشیو در گزارش حسابرسی ثبت می‌شود؛ فایل مرتبط با پروژه همچنان از بخش پروژه قابل دریافت می‌ماند.

## حفاظت و عملیات

- نشست مدیریتی opaque و سمت‌سرور است؛ رمزها با Argon2 ذخیره می‌شوند؛ فرم‌ها CSRF دارند و کوکی نشست در تولید فقط روی HTTPS ارسال می‌شود.
- ورودی‌های خصوصی تنها در گفتگوهای خصوصی پذیرفته می‌شوند. فایل‌ها با نام تصادفی، محدودیت حجم، بررسی امضای محتوا و بیرون از مسیر وب ذخیره می‌شوند. فایل‌های فشرده هرگز استخراج یا اجرا نمی‌شوند.
- ورودی پیام‌رسان بعد از ثبت پایدار صف، offset می‌گیرد. صف ارسال هم پایدار و قابل تکرار است. پلتفرم‌ها تضمین idempotency برای `sendMessage` نمی‌دهند؛ در رخداد قطع ارتباط پس از ارسال موفق و پیش از ثبت نتیجه، یک پیام تکراری ممکن است دیده شود.
- برنامه هیچ سرویس هوش مصنوعی یا تحلیل خارجی به کار نمی‌گیرد و متن پروژه را به ارائه‌دهندهٔ ثالث نمی‌فرستد.
- فایل آرشیو و فایل `.env` آپلودشده در بستهٔ قدیمی وارد این نسخه نشده‌اند. پیش از انتشار عمومی، توکن‌های داخل بستهٔ قبلی را باطل و دوباره صادر کنید.

برای backup رمزگذاری‌شده با `age`، `BACKUP_RECIPIENT` را تنظیم و `sudo bash scripts/backup.sh` را اجرا کنید. جزئیات در `docs/SECURITY_FA.md` آمده است.
